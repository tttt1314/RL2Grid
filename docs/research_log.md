# 研究線一：RL2Grid bus14 基準重現與安全強化學習（LagrPPO）失效機制定位

## 研究問題

1. 在 GCP VM（`g2op-train`，`c2d-highcpu-32`）上重現 Marchesini et al.（*RL2Grid*, arXiv 2503.23101v2）於 `bus14` 環境的所有強化學習基準結果。
2. 診斷為何論文與本次重現實驗中，帶有安全約束的 `LagrPPO` 演算法表現遠差於無約束的 `PPO`，並據此設計合理且穩定的安全電網控制方法。

**背景設定與名詞定義（方便獨立閱讀）**
- **模擬電網（`bus14`）：** Grid2Op 的 `l2rpn_case14_sandbox`（難度 0，14 個匯流排、20 條輸電線）。資料集包含 1,004 個一個月長度的負載／發電情境劇本（稱為 `chronics`），每個完整情境最長約 $T_{\max} = 8064$ 步（每步 5 分鐘，共 28 天）。
- **兩種動作空間與三種操作模式：**
  - **拓撲控制（topology，離散動作）：** 切換變電站匯流排接線或線路開關。分為三種設定：**原版（Vanilla）**完全由 RL agent 自己每步決策；**閒置啟發式（Idle heuristic）**在所有輸電線負載率皆低於 95% 時自動執行「不做動作」，只在電網接近過載時交給 RL 決策；**回復啟發式（Recovery heuristic）**在電網安全時自動重連斷線並逐步把拓撲還原成預設狀態。
  - **發電再調度（redispatch，連續動作）：** 連續調整各發電機的出力分配。
- **核心評估指標：**
  - **存活率（ $\text{survival} = T_f / T_{\max} \in [0, 1]$）：** 電網撑過的時間步數除以該情境總長（1.0 代表整個月都沒停電）。本專案每組實驗取訓練結束前**最後 3 次確定性評估的平均**（每次 10 個完整情境，共 30 個情境）。
  - **訓練過程診斷指標：** 評估期平均每情境累積懲罰（`cost_return`），以及 `LagrPPO` 每次更新（每 10 萬步一輪，3M 步共 30 輪）印出的統計量——更新前／後的拉格朗日乘數 $\lambda$ 與實際套進損失函數的懲罰權重 $\nu = \text{softplus}(\lambda)$、雙變數更新用來對照門檻的成本統計量 $\hat{J}_C$、每輪策略變動幅度 `approx_kl`（近似 KL 散度）、觸發 PPO 裁切的比例 `clipfrac`、平均情境長度 `ep_len`，以及用於正規化電網觀測值的移動平均統計量 `obs_rms`。
- **安全約束演算法 `LagrPPO` 的兩種約束：**
  - 演算法在更新策略時，會同時最大化預期獎勵並最小化 $\nu$ 倍的預期懲罰：損失函數為 $(-L^{\text{CLIP}}_R + \nu \cdot \text{cost\_surrogate}) / (1 + \nu)$。
  - **失敗約束（程式選項 `constraints_type=1`，簡稱失敗約束 `C1`；論文稱 LSI）：** 論文公式原寫為缺電與孤島指標之和，但程式碼實際實作為「情境因電網崩潰提早結束的那一步記 cost = 1，其餘步數皆為 0」；論文 Table F.1 設定門檻為 **`50`**，並與「所有平行環境最後 8,000 步的總失敗次數 $\hat{J}_C$」比較來調整 $\lambda$。
  - **過載與斷線約束（程式選項 `constraints_type=2`，簡稱過載約束 `C2`；論文稱 TLO）：** 每一步 cost = 超過熱限值的輸電線數量＋非維修與非攻擊造成的斷線數量；論文 Table F.1 設定門檻為 **`0`**。

## 目前結論（2026-11-25 20:02 UTC+8 更新）

**已完成 `bus14`（`seed 0`）全部 14 組基準重現（14/14 成功完成），並透過關閉約束對照、加上完整追蹤紀錄重跑等 4 組診斷實驗（累計 18/18 成功完成，0 失敗）精確定位為何「失敗約束版 `LagrPPO`（C1）」學不起來：**
1. **最直接的壞因是成本項缺乏 trust region 保護（提案 O5）：** `LagrPPO` 對獎勵項有做標準化與 PPO 比率裁切，但對成本項完全沒做標準化、也沒做裁切；當實際懲罰權重 $\nu \approx 1.35\text{–}1.70$ 佔了總梯度約六成時，首輪策略變動 `approx_kl` 就爆衝至 `0.707`（過載約束版更達 `5.523`），直接打壞策略更新。只要把懲罰權重鎖近於 0（其他超參數與網路大小完全不變），300 萬步存活率立刻從 **`0.320 / 0.355`** 回升至 **`0.579`（訓練中最高 `0.643`）**，且首輪 `approx_kl` 降至 `0.049`。
2. **雙重推論更正（推翻原先對超參數與 $\lambda$ 走勢的簡化猜測）：** 原本推測「失敗約束版低分主要是學習率過大與更新輪數過多（提案 O6）」已被推翻；同時也發現原以為「失敗約束的 $\lambda$ 全程低於門檻 50 會往下掉（提案 O2）」並不準確——實際上前 14 輪（前 140 萬步）因電網經常幾十步內就停電，總失敗次數高達 `1216 → 60`（大於門檻 50）先把 $\lambda$ 一路推高到 `1.418`；到後半段失敗次數確實降到門檻以下（`48 → 14`），卻受限於 Adam 累積動量與 300 萬步總共只有 30 輪更新，導致 **$\lambda$ 仍繼續慣性爬升並被鎖死在 `1.504` 高點**。
3. **額外程式碼發現（post-hoc）：** 只要開啟任何安全約束，環境的過載獎勵函數 `OverloadReward(constrained=True)` 就會把「斷線懲罰」自動設為 `0.0`（無約束 `PPO` 則有 `-1.0` 懲罰），使得失敗約束版在 reward 與 cost 兩側都完全看不到未崩潰前的斷線訊號。

（註：以上實驗數據目前皆來自 `seed 0` 單次結果，仍需多 seed 驗證。）

**目前最強的證據（2026-11-25 20:02 UTC+8）：**
1. **單因子關閉約束對照（`E1` vs. `E2-C1`）：** 完全相同的環境與超參數，僅把雙變數權重鎖死在 $\nu \approx 2\times 10^{-9}$，300 萬步平均存活率由 `0.3552`（原基準 `0.3197`）跳升至 **`0.5786`**（最高 `0.6428 @ 2.8M`），首輪 `approx_kl` 由 `0.70715` 降為 `0.04863`。
2. **兩次獨立執行的雙變數終點高度一致：** 原基準失敗約束檔與新重跑帶 log 版本的最終 $\lambda$ 分別為 `1.4806` 與 `1.503`（初始 `1.0`），過載約束版則分別為 `1.3626` 與 `1.355`，確認「前衝後鎖」與「初期尺度撐大 Adam 二階矩」可重現。
3. **過載約束的震盪與末期失控（`E2-C2`）：** 雖在 230 萬步達到單次評估高峰 `0.8122`，但在 150–170 萬步間因 `approx_kl` 連爆 `0.88 / 1.26 / 0.69` 導致存活率當場摔至 `0.105`，且最後 3 次評估的過載／斷線違規平均飆高到 **`93.90`**（前 200 萬步多在 `23–46`）。

## 尚未解決的問題

1. **為何「關閉約束的 LagrPPO（`0.5786`）」仍低於「同在 300 萬步的無約束 PPO（`0.7104`）」？** 這個約 `0.13` 的剩餘差距，尚未拆清有多少來自 `OverloadReward(constrained=True)` 拿掉斷線懲罰、多少來自 batch 大小差異（每輪 10 萬步共更新 30 次 vs. 每輪 2 萬步共更新 150 次）與 300 萬步的學習率退火速度。
2. **單一隨機種子波動與尚未驗證跨情境泛化：** 目前全數實驗皆僅跑 `seed 0`，每次評估只有 10 個情境（95% 信賴區間半寬約 ±0.21）；且訓練與評估共用同一池 1,004 個 `chronics`，加上舊 checkpoint 未存觀測正規化統計量 `obs_rms`，尚未在嚴格未見過的測試情境上量過泛化落差。
3. **非 RL 基準進展（`Idle`／`Reco` 已補測，`MILP` 因環境套件缺漏略過）：** 2026-11-25 已於 VM 透過 `tools/eval_baselines.py`（100 個情境）量測「不做動作（Idle）」與「自動重連（Reco）」基準（拓撲與發電再調度皆為 `0.2394 ± 0.0382`，與論文 Table 2 的 `0.18` 趨勢相近、但與論文 Table 3 的 `0.00` 有差異）；基於 DC 潮流最佳化的 `MILP` 基準因 VM 未安裝 `grid2op_milp_agent`／`l2rpn_baselines.OptimCVXPY` 而略過（為避免破壞既有 RL 套件相依性暫不額外安裝）。
4. **演算法改進實驗進行中：** 針對以上診斷出的問題（成本項沒做標準化與 PPO 裁切、Adam 鎖死與過衝、獎勵與成本的時間視野不一致、以及「早點停電反而能躲掉過載成本」的結構漏洞），Batch 1 已於 2026-11-25 21:04 UTC+8（`13:04 UTC`）在 VM 上啟動執行。

## 下一步候選

- **候選 A（主線第一階段）：單獨驗證修復「成本項無 trust region 保護」的消融實驗。** 在 `LagrPPO` 中替 cost advantage 補上標準化（減去平均並除以標準差）、套用與獎勵項對稱的 PPO clip（最大化取悲觀上界），並開啟 `--target-kl` 提早停止單輪過大更新；觀察這三項本身是否就能消除 `approx_kl` 暴衝並顯著拉高 C1／C2 存活率。
- **候選 B（主線第二階段）：整合 PID Lagrangian 與重新設計電網 CMDP。** 以比例—積分—微分（PID）控制取代 Adam 更新 $\lambda$ 以解決過衝鎖死問題；並修正 CMDP 定義（將提早停電視為進入吸收懲罰狀態以消除早死逃逸誘因、替 cost critic 採用與長時間尺度一致的較大折扣 $\gamma_c$、並用完整 episode 統計量對齊門檻單位）。
- **候選 C（補齊評估基準與泛化切分）：** 在環境建立端加入 `--chronics-split` 切出固定未見過測試集，並把 `obs_rms` 寫入 checkpoint，跑代表性組別量測真正泛化落差；同時補跑 `Idle` 與 `MILP` 非 RL 基準，以及視需要補跑 `seed 1 / 2`。

## 時間軸

### 2026-11-18 16:49 UTC+8 · 基礎設施：全演算法非同步收集、平行評估與 Spot VM 可接續排程
- **改動位置：** `common/async_collector.py`、`env/eval.py`、`tools/queue/run_queue.py`、`tools/setup_vm.sh`、`docs/async_collect.md`（commits `89fe6bc`～`1e77f13`）
- **背景與問題：** 原始碼使用 `gym.vector.AsyncVectorEnv`，每步都強制等待 50 個平行環境中最慢的一個回傳。開啟啟發式時（安全期間內部連續模擬幾十到幾百步），同一時刻 51 個程序僅約 2 個在運作，速度只有約 20 steps/s（SPS）；同時評估預設只跑 3 個情境，數值在 29%–97% 間劇烈跳動且單執行緒評估拖慢訓練。
